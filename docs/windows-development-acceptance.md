## Источники доказательств

`Windows development acceptance` собирает текущий Tauri/native код на Windows
и обращается прямо к `https://api.prettylisavpn.com`. Native HTTP transport,
защищённое хранилище и React работают штатно; API-imitation server не запускается,
VITE_UI_REVIEW_VPN не включается. Артефакт содержит только безопасный JSON-отчёт
и настоящие снимки окна. SHA/run/attempt и окончательные результаты — в PR #17.
Обычный `Windows UI review` отдельно подтверждает fixture-сценарии и вёрстку.

Из Cloud HTTPS пока недоступен из-за недоступного inherited proxy. Прямой прогон
выполняется на GitHub Windows runner с существующими development SSH credentials.
SSH проверяет known_hosts и совпадение DNS alias с документированным VPS.

Временный аккаунт создаётся штатными User/Device/AuthSession сервисами внутри
запущенного development container. У него адрес `windows-acceptance-RUN-ATTEMPT`
в example.com, нет писем, VPN-пиров и платежей. Короткие credentials передаются
только по verified SSH в приватный временный файл runner и затем удаляются.
Always-cleanup удаляет только аккаунт точного RUN/ATTEMPT. Существующие аккаунты,
их устройства, подписки, каталог и конфигурация провайдера не изменяются.

## Ручной OTP без сохранения кода

По решению владельца OTP поставлен на паузу. Автоматические push-прогоны
не запрашивают письмо и отдельно отмечают OTP как deferred, без утверждения о
проверенном входе. Ручной сценарий включается только через workflow_dispatch
с `manual_otp=true`, после согласования доступности владельца. Если включённый
сценарий не получает готовность или свежий код, прогон завершается ошибкой.

Перед запросом письма runner создаёт одноразовую RSA-2048 пару. Он сначала
ждёт зашифрованное подтверждение готовности владельца читать почту и лишь после
него запрашивает письмо. Это не даёт коду истечь, пока владелец отсутствует. В артефакт попадает
только публичный ключ с run ID и nonce; приватный ключ остаётся в runner temp.
Переданный владельцем код шифруется RSA-OAEP/SHA-256 для этого ключа. Runner читает
только ciphertext из `acceptance-otp.json` отдельной ветки `acceptance-otp-RUN`,
проверяет run/nonce и вводит код в штатную форму. Plaintext OTP не помещается в
GitHub inputs, git, Actions log, отчёт или screenshot. Ветка с ciphertext не входит
в PR. После проверки пользовательский аккаунт выходит. Cleanup отзывает только новый
runner device по его уникальному installation UUID и email владельца; существующие
устройства не отзываются. Отсутствующий/просроченный код оставляет сценарий непройденным.

## Платежи и границы приёмки

Отдельный job использует одноразовый PostgreSQL/Valkey CI. Проверяются оформление,
отложенное подтверждение, отказ, отмена, повторы уведомлений и request ID, гонки,
сбой между receipt и settlement, восстановление новым worker, продление ровно
одного периода, смена mandate и отмена без потери срока, все маршруты/валюты.
Это реальные сервисы/БД с тестовым провайдером, не банковские операции. Windows
для SANDBOX остаётся read-only; положительные LIVE UI-тесты — только fixtures.

WireGuard data plane нельзя объявлять проверенным по GET стран или screenshot:
для него нужны официальный проверенный DLL, elevated Windows и отдельная
проверка трафика/адреса/остановки пира. См. windows-wireguard-runtime.md.
SMTP receipt не доказывает inbox; открытие поддержки не доказывает отправку письма.
