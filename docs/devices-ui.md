# Устройства — Windows 0.6.1

В настройках устройства сохраняют имя от backend. Под ним вместо платформы:

- `id: …` — последние 12 символов существующего UUID устройства. Это стабильная
  метка, не имя ОС и не секрет. Полный ID доступен в подсказке и подтверждении
  отзыва. Если сокращения в списке совпадают, показываются полные UUID.
- `добавлено:` — существующее `created_at` из GET /devices.
- `последний вход:` — необязательное `last_login_at` либо «нет данных».

Даты отображаются в часовом поясе текущего устройства, с датой и временем;
ISO timestamp остаётся в `time[datetime]`. Имя и остальные метаданные не
выдумываются клиентом. Статус и отметка текущего устройства сохранены.
Два предложения о лимите/освобождении места разделены явным переносом.

## Совместимость и будущий backend

В backend source 0.1.0 GET /devices возвращает `created_at`, `updated_at`,
`revoked_at`, но не время входа. `updated_at` меняется при редактировании
метаданных и отзыве; повторный вход с тем же именем может его не менять.
Нельзя выдавать это поле или дату регистрации за последний вход.

Клиент подготовлен к совместимому необязательному полю
`last_login_at?: string | null` в DeviceResponse. Если поле передано, HTTP-адаптер
проверяет ISO timestamp. Отсутствующее/null значение означает «нет данных».
Текущий backend работает без изменений; source версия backend не повышалась.

Будущая задача backend: хранить для устройства время последнего успешного
подтверждения входа (OTP) в UTC и возвращать его в ответах устройств.
Обновление токена, просмотр списка, VPN-connect и изменение имени не являются
новым входом. Для старых записей без достоверного события возвращать null,
не восстанавливать дату из updated_at. Нужны миграция и тесты владельца/авторизации,
успешного/неуспешного входа и неизменности при refresh. Этот этап пока отложен.

Native review использует два синтетических устройства: одно с датой входа,
другое без неё. Это проверка UI, а не подтверждение работы нового поля backend.
