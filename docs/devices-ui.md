# Устройства — Windows 0.6.1

В настройках устройства сохраняют имя от backend. Под ним вместо платформы:

- `id: …` — последние 12 символов существующего UUID устройства. Это стабильная
  метка, не имя ОС и не секрет. Полный ID доступен в подсказке и подтверждении
  отзыва. Если сокращения в списке совпадают, показываются полные UUID.
- `добавлено:` — существующее `created_at` из GET /devices.
- `последний вход:` — необязательное `last_login_at` либо «нет данных».

Даты отображаются в часовом поясе текущего устройства, с датой и временем;
ISO timestamp остаётся в `time[datetime]`. Имя и остальные метаданные не
выдумываются клиентом. Статус и отметка текущего устройства сохранены.
Два предложения о лимите/освобождении места разделены явным переносом.

## Backend 0.2.0

Миграция `0018_device_last_login` добавляет nullable `timestamptz` без backfill
и без default. Старые устройства возвращают `last_login_at: null`, пока не пройдут
успешный OTP-вход. Значение записывается в той же транзакции, что создание auth
session и выдача access token, в том числе при повторном входе на той же installation.
Отклонённый/повторно использованный OTP, blocked user, device limit и ошибка БД
не меняют дату. Refresh, GET /devices, rename, revoke и VPN-connect её не заменяют.
Поле возвращается в GET /devices, DELETE /devices/{id} и login device response.

Отзыв принадлежит только владельцу: неизвестный/чужой ID даёт одинаковый 404.
Device, auth sessions и PENDING/ACTIVE VPN sessions отзываются одной транзакцией.
Терминальные VPN rows с `peer_removed_at=null` — durable cleanup intent;
node I/O выполняется после commit. Нода недоступна — отзыв остаётся успешным,
а reconciler повторяет idempotent DELETE после восстановления. Это eventual
удаление peer, а не обещание мгновенной сетевой блокировки при недоступной ноде.

Повторный запрос с другого действующего устройства идемпотентен и не меняет
revoked_at; event создаётся один раз. После отзыва текущего устройства его прежние
access/refresh credentials недействительны, поэтому повтор с ними получает 401.
Provisioning и revoke сериализованы device row lock; cleanup защищён row/advisory
locks. IP и public key не переиспользуются до подтверждения удаления старого peer.

Backend package version: 0.1.0 → 0.2.0 (совместимая возможность); Windows 0.8.0
не меняется. Наличие кода и CI не означает развёртывание на development.
Новый код может работать со старым клиентом. Перед rollback приложения можно
оставить additive column в БД; downgrade удаляет last_login_at и требует отдельного
решения о допустимости потери этих новых данных.

## Проверка интерфейса

Native review поддерживает записанные ответы нового backend из изолированной
CI PostgreSQL. Для тестового аккаунта используется разрешённый владельцем
`kenromka@yandex.com`; авторизация в UI симулируется. OTP, persistence и отзыв
проверяются отдельно через настоящий FastAPI/service слой с тестовыми adapters.
Скриншоты отмечают точный source/build SHA, backend version и provenance данных.
Существующие устройства и токены аккаунта на development не изменяются этим review.
