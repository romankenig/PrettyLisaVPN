# Домашний экран Windows — 0.4.0

## Выбор подключения

Источник доступности — существующий GET /vpn/countries. В выпадающем списке три
группы: автопилот; до трёх доступных стран по убыванию quality; все available=true
страны по русскому алфавиту. При равном рейтинге порядок алфавитный. Рейтинг —
серверный quality от 0 до 100, не измеренная клиентом скорость или ping.

Строка содержит локальный круглый SVG-флаг, русское название и рейтинг; у
автопилота — глобус. Circle Flags включён в приложение с MIT-лицензией, без
загрузки картинок во время работы. Список поддерживает мышь, стрелки, Home/End,
Enter/Space, Escape и поиск по начальной букве. Переполнение прокручивается
внутри списка, окно остаётся 960 × 640.

Выбор хранится отдельно для аккаунта в localStorage под
prettylisavpn.location.<user-id>; только mode/country_code. При первом запуске,
повреждённой/недоступной storage или недоступной выбранной стране — автопилот.
Список обновляется раз в минуту и вручную; при ошибке старые рейтинги не разрешают
новое подключение. Во время подключения/активного туннеля выбор заблокирован.
Кнопка и подтверждённый VPN orchestration status находятся под выбором; справа
расположен блок «что защищаем». Connected по-прежнему требует проверки интернета.

## Аккаунт и тариф

PREMIUM отображается со ⭐, PLATINUM — с 💎, FREE — без символа. Клиент принимает
PLATINUM в /me и auth-ответах, но backend этой задачи не вводит новый тариф,
платёжные правила или права. Backend в исходниках остаётся 0.1.0.

На Home над названием продукта стоит «home», email подписан «аккаунт».
Статичный блок «статус: активен» удалён: он не отражал ответ backend.

## Режим трафика

Справа «что защищаем»: «весь трафик», «только выбранные сайты», «кроме выбранных
сайтов». Первый соответствует текущему FULL_TUNNEL. Два остальных — отключённые
карточки с явным «скоро», по решению владельца: сейчас только UI, маршрутизация
позже. Они не меняют настройки, маршруты, DNS и не сохраняют неработающий выбор.
Текущий selected radio показывает режим профиля; фактическое соединение по-прежнему
определяется статусом слева. Реализация доменных include/exclude и редактора списков —
отдельная задача с проверкой DNS/CDN, IPv4/IPv6, смены адресов и обхода маршрутов.

## Сведения о состоявшемся подключении

Только после CONNECTED слева показана небольшая подпись с alpha 58%: протокол,
транспорт, публичный адрес:порт и шифрование/MTU. Раскрытие «параметры подключения»
показывает доступные DNS, адрес туннеля, маршруты, keepalive, маскировку и публичный
ключ сервера. ConnectionDetails — отдельная проекция публичных параметров, а не
сырой config/diagnostics. Discovery модели по-прежнему не содержат инфраструктуру.

Данные берутся у адаптера действующего туннеля; WireGuard использует native peer
readback и actual transportMode/publicEndpoint, а не первый предложенный candidate.
MTU 1280 соответствует фиксированной настройке WireGuardNT. DNS/client address
показываются только при совпадении действующего peer с конфигурацией, которую этот
адаптер успешно применил. После восстановления процесса отсутствующие параметры
не выдумываются; другие адаптеры без реализации metadata возвращают «недоступны».

Чтение не меняет состояние VPN, ограничено 5 секундами в UI; после отключения,
смены сессии или ошибки старые сведения не показываются. Приватные ключи, токены,
credential/trust refs и произвольные поля runtime не попадают в UI/логи. Полного
экспорта WireGuard-профиля нет: ручная настройка также требует отдельного профиля
с необходимыми ключами; публичного описания самого по себе недостаточно.

## Текущая локация

Внизу левой панели показаны фактически наблюдаемые город, страна и внешний IP.
Источник — отдельный PublicLocationProvider; основной backend не меняется.
Default: GET https://ipwho.is/, настройка VITE_PUBLIC_LOCATION_URL позволяет
заменить endpoint на совместимый ответ: success=true, ip, country_code, city.
Приватные аккаунтные токены и cookies провайдеру не передаются; результат не
сохраняется и не логируется. Геолокация относится к IP, а не к GPS/почтовому адресу.

Обновление: при открытии экрана, раз в 60 секунд после завершения запроса,
при focus/online и после смены состояния сети/VPN. Timeout запроса — 8 секунд.
Во время переходных фаз старый адрес скрыт; запросы прежней сети отменяются,
поздние ответы игнорируются. После ошибки показано «не удалось определить»
и повторная попытка; ошибка не меняет VPN status и не блокирует отключение.

Страна выбранного сервера не подставляется вместо наблюдения. При split routing,
другом VPN/прокси или ошибке маршрутизации может отображаться другая страна — это
фактический результат запроса, а не доказательство исправного VPN. Если сервис
не возвращает город/страну, показаны «город неизвестен»/«страна неизвестна».

UI review использует отдельный loopback fixture /public-location с документальным
IP 203.0.113.42. HTTP endpoint разрешён только в test-окружении. Fixture не
подтверждает доступность реального провайдера или production VPN; проверить это
на реальном Windows-клиенте при отключённом и включённом VPN остаётся отдельным
пунктом проверки интеграции. Провайдер и его ограничения заменяемы адаптером.

## Проверка интерфейса

Native UI review содержит дополнительный явно синтетический connected-сценарий.
Только при environment=test и VITE_UI_REVIEW_VPN=1 main.tsx внедряет локальный
review-адаптер tunnel/key dependencies; основной protocol/connection manager
используются без замены. Native VPN IPC не вызывается, реальные ключи/туннель
не создаются. Без флага (в том числе production) используется прежний native path;
Vite удаляет неиспользуемый fixture из обычной сборки. Capture проверяет маркер
review-сборки перед любой VPN-кнопкой. Окно и оконные действия остаются нативными.

Сервер fixtures создаёт синтетические sessions только с --simulate-vpn; по умолчанию
возвращает 404 на создание VPN-сессии. Connected screenshots проверяют подпись,
раскрытие и исчезновение параметров, а не production VPN.
