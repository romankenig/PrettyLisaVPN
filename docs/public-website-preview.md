# Публичный сайт PrettyLisaVPN: preview 0.1.0

Историческая запись первой версии. Текущая структура 0.2.0, переводы, прямые
скачивания и условия публикации описаны в [redesign handoff](public-website-redesign.md).
Пометки черновика и публичная readiness-страница удалены по следующему поручению
владельца; список подготовки к приёму платежей остаётся внутренним.

Дата проверки: 2026-11-03. После проверки preview владелец отдельно поручил
опубликовать текущую версию на https://prettylisavpn.com. Публикуется именно
черновик с видимыми пометками и выключенной оплатой. Это разрешение не означает
утверждения документов, включения платежей или merge PR50.
По последнему решению владельца фокус только на Cardlink; остальные провайдеры
отложены и не показаны как способы оплаты.

## Версии и совместимость

Новый компонент `sites/public-website/package.json`: отсутствовал → **0.1.0**.
Это первая реализация сайта, поэтому собственная начальная версия. Backend 0.31.0,
Windows 0.25.0, Android 0.21.0 остаются без изменений. База данных, существующие API,
авторизация, VPN и клиентская навигация не меняются. Миграция не требуется.

Основание ветки: `eed488ac1fe5dd4fbb8ffcbc0d320340bcf6d465` после merge PR47 и PR49.
Фактический проверенный remote HEAD и все CI run/attempt фиксируются в PR после
последнего push; это позволяет не создавать новый commit только ради номера CI.
Артефакт `PrettyLisaVPN-website-preview-<build SHA>-<run>-<attempt>` включает
`build-identity.json`. Его поле `deployment` описывает состояние в момент сборки;
фактическая публикация фиксируется отдельно в PR и журнале выкладки на сервере.
См. [размещение и откат](../infra/deployment/README.md#public-draft-website).

## Что реализовано

| URL | Поведение |
| --- | --- |
| `/` | Возможности Android/Windows, выбор трафика, Free, путь подключения, FAQ |
| `/plans/` | Free/Premium, RUB/USD, срок, устройства и ручное продление |
| `/checkout/` | Сводка условий; комиссия и итог неизвестны; оплата заблокирована |
| `/payment/` | Честный статус подключения Cardlink без утверждений о партнёрстве |
| `/setup/` | Установка Android/Windows, тестовые загрузки, действия при неполучении доступа |
| `/account/` | Путь к существующему управлению подпиской в приложениях |
| `/support/` | Валидация обращения, подготовка письма, без автоматической отправки |
| `/legal/` | Навигация по шести отдельным черновикам |
| `/legal/seller/` | Продавец и контакты |
| `/legal/terms/` | Проект соглашения/оферты |
| `/legal/privacy/` | Реально известная обработка данных и отмеченные пробелы |
| `/legal/payments/` | Оплата, продление и отмена |
| `/legal/refunds/` | Возвраты и претензии: порядок ещё не утверждён |
| `/legal/acceptable/` | Проект допустимого использования |
| `/readiness/` | Незакрытые условия и вопросы провайдеру |
| `/404/` | Страница ошибки; неизвестные адреса получают HTTP 404 |

Сохранены Rubik, фирменная палитра и композиция знака/названия из Windows.
Нет сторонних трекеров, внешних шрифтов, карточной формы или фиктивных отзывов.
Все страницы помечены preview/noindex, документы — неутверждёнными черновиками.
Локальный сервер использует CSP, запрет iframe/form navigation, no-referrer,
no-store, безопасный статический корень и не пишет access logs.

## Аудит данных для политики

Изучены фактические модели/сервисы backend, config, deployment и клиентский split.

| Обработка | Доказательство/граница |
| --- | --- |
| Email, UUID, статус и даты аккаунта | Модуль users; общий retention/удаление не согласованы |
| Платформа, имя, ID устройства, даты входа/отзыва | Модуль devices; срок хранения после отзыва не подтверждён |
| OTP и сессии | Модули auth, config.py; defaults 5 минут / 15 минут / 30 дней — сроки действия, не обещание физического удаления |
| Тарифы, периоды, операции и idempotency | Модули billing, subscriptions; live provider выключен, финансовый retention не согласован |
| VPN-сеансы и технические метрики | Control plane: сервер/способ/время/доступность; без заявления об отсутствии всех журналов |
| Аналитика активности и тарифов | product_analytics/service.py: дневные данные 180 дней; срок исходных событий отдельно не подтверждён |
| Поддержка и снимки экрана | support/delivery.py: очистка содержимого/вложений рабочей БД через 30 дней; mailbox/backups отдельно не подтверждены |
| Выбор сервисов и режимов | Сохраняется в приложениях; это настройки маршрутизации, не история посещений |
| Сайт | Нет cookies приложения, localStorage, внешних шрифтов/аналитики; currency в URL; support текст не передаётся серверу |
| Инфраструктура | SMTP Timeweb, VPN-узлы, сервисы IP/локации; договоры, регионы БД/backup, DNS/IP-получатели и журналы требуют подтверждения |

До финальной политики нужно утвердить правовые основания, сроки/процедуру удаления,
обработчиков, регионы хранения/передачи и доступ администраторов. Нельзя заменять эти
пробелы утверждениями «без логов» или абсолютной анонимностью.

## Что получить и реализовать до запуска

1. Адрес продавца для письменных претензий; подтвердить полноту реквизитов для НПД.
2. Утвердить оферту, действие заключения договора и запись принятой редакции.
3. Согласовать правила/расчёт возврата, сроки претензий, выдачу/исправление чеков НПД.
4. Утвердить срок активации, поддержку, ограничения трафика/скорости и правила AUP.
5. Завершить инвентаризацию данных и политику обработки/удаления.
6. Получить допуск Cardlink для VPN российского самозанятого, валюты и комиссии.
7. В существующем backend реализовать mockable Cardlink adapter, серверные quotes,
   проверенные callback/status, идемпотентное начисление доступа, сверку и возвраты.
8. Добавить account-scoped историю заказов/статусов и связать оплату с OTP-аккаунтом.
   Текущая `/account/` — инструкция, не имитация вошедшего пользователя.
9. Организовать общедоступные проверенные загрузки клиентов: нынешние GitHub ZIP
   требуют доступа к репозиторию и не являются каналом поставки новым покупателям.
10. Проверить реальный путь оплата → подтверждение → доступ и отдельно разрешить
    запуск продаж. Разрешена публикация черновика по HTTPS; готовым магазином он не стал.

До этого сайт **не готов к подаче как законченный магазин**. Документы не утверждены,
приём платежей отключён; технический preview готов к проверке содержания/интерфейса.

## Вопросы Cardlink и источники

Вопросы подготовлены, но в поддержку не отправлялись: владелец решил вернуться позже.

- Допускаются ли VPN и продавец — физлицо на НПД в России? Какие документы нужны?
- Какие карты/валюты доступны; комиссия продавца/покупателя и итог до оплаты?
- Как проверять уведомления, сверять неизвестный результат, повторять запрос без дубля?
- Есть ли полный/частичный возврат; как обрабатываются споры и комиссия?
- Каков порядок чеков НПД, есть ли связка с «Мой налог»?
- На будущее: API рекуррентных списаний, фиксация согласия, отмена/отзыв полномочия?

До текущего сужения задачи проверены [официальные требования Cardlink](https://cardlink.link/en/reference):
есть ограничение на связь проекта с криптовалютами. Его применимость к совместному
приёму оплаты не выяснена. Сейчас криптооплата не реализуется вообще, не скрывается
от модерации; при возвращении к ней нужен письменный ответ Cardlink до интеграции.

Остальные источники: [API Cardlink](https://cardlink.link/en/reference/api),
[условия Cardlink](https://cardlink.link/en/terms-of-use),
[ФНС о чеках НПД](https://www.nalog.gov.ru/rn19/news/activities_fts/16641439/),
[ФНС об обязанности выдавать чек](https://www.nalog.gov.ru/rn40/news/tax_doc_news/16645245/),
[Роспотребнадзор об отказе от услуг](https://13.rospotrebnadzor.ru/faq/48899).
Эти страницы использованы для перечня проверок, не как подтверждение одобрения магазина
или готовая индивидуальная юридическая оценка.
